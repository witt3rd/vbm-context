# 0001: vbm-context, verified typed agent state

## 1. What and why
An agent that carries a growing transcript pays for it every step and can lose its task inside it. This library specifies the alternative as data and total functions: a **typed state** (the goal verbatim, the done-when obligations, facts with provenance, open questions, a working set of handles into the journal) that replaces the transcript; **typed patches** the model writes back instead of a whole new state; a **total, deterministic, idempotent compaction** that bounds the size and can never drop the goal, an obligation or a pinned fact.

Proved is the *machine*; whether a model succeeds with it is **empirical, never claimed proved**. What a patch means (that an obligation really is met) is the model's claim; a checker script can verify a mechanical one.

## 2. Design choices
- **Patches, not rewrites.** The model returns `List Patch`. A patch is a typed event (add a fact, meet an obligation, set the plan, ask, touch a handle); "obligation met" is an explicit, checkable event, and the output the model must write per step is small.
- **Compaction is a projection**, not a re-summary: it caps each list and keeps the protected parts, so applying it twice equals applying it once.
- **Protected facts** survive compaction: a pinned fact (a rewrite of its key stays pinned), or a fact an obligation that is not yet met cites by key (the pin rule: what a pending obligation rests on is never compacted away). The size bound therefore reads `4n + protected facts`: protecting is the caller's budget decision, stated in the theorem.
- **History is retrievable, not carried.** Facts keep a `src` handle into the journal and the working set holds handles, so what compaction drops stays reachable outside the state. The journal itself is out of scope here.
- **Scope.** Pure data and functions over Lean's `Init`. No model call, no network, no prices, no model names, no tokenizer (`State.size` counts items; a byte-level size needs a rendering, a later slice).

## 3. Slices
C1 (landed with the scaffold): `State`, `Patch`, `apply`, `compact`, `step`; claims: goal, obligations and pinned facts kept by any patch list and any compaction (`step_keeps`), `compact_idem`, `compact_size`. C2: the pin rule (an obligation names the fact keys it rests on; a fact that is pinned or cited by an unmet obligation is protected: `compact_protected`, `compact_cited`, `step_protected`) and the one-fact-per-key invariant. Size reads `4n + protected facts`. P1: the primary prompt as typed, versioned data with a pure, injective rendering that opens every context (`render_injective`, `context_take`). T1: the ephemeral tail as data (`EphemeralSpec`: ordered slots with byte caps, a total cap) and its pure rendering with the typed dropped-slots marker and the redaction hook as a parameter. T2: the request and the history around the tail (`request`, `advance`, `historyOf`, `fullRequest`: the render equation, a history that never holds a tail, identical prefix segments across calls). X1: the excerpt (the pointer spill) as a pure view: a tool result over its budget is shown as its head and tail, whole characters, with a note naming the tool, the omitted count and the handle under which the caller keeps the whole text (`excerpt`, `excerpt_of_fits`, `excerpt_len_le`, `excerpt_keeps_head_tail`, `excerpt_omitted`, `excerpt_ends_nonempty`); the excerpt is a view, nothing is capped in what is stored, and writing the whole text is the caller's I/O. E1: old-block elision (`Block`, `elideOld`, `Ctx.elide`): bulky blocks older than the latest `keepTurns` turns become a one-line placeholder with a handle to read back, in one batch; every block is kept (`elideOld_map`), the first block and the latest turns are never edited (`elideOld_head`, `elideOld_recent`, `elideOld_last`), an elided block is never elided again (`elideOld_elided`), the operation is idempotent (`elideOld_idem`), strictly shrinks when it changes anything (`elideOld_cost_lt`) and counts one epoch bump per change (`ctx_elide_epoch_iff`, `ctx_elide_idem`). **Context reduction does not depend on the model's window**: the budgets are two fixed numbers owned in one module (`VbmContext/Budget.lean`: `excerptBytes` = 8192 bytes of head and tail, `keepTurns` = 4 turns), no function takes a window or a token limit, and a tool that needs another excerpt budget passes it as data. Next, not started: the state rendering with a stable prefix and `parse (render s) = s`; provenance validity and redaction; a per-step spend bound with prices as a parameter.

**REINSTATE the vectors gate as a compiled-versus-kernel DIFFERENTIAL in the SAME slice that first ships the compiled path to a consumer (the consumer wiring): not to be forgotten.** The first vectors gate (concrete scenarios run through the compiled library, expectations written by the author) was removed: its only reference was the author's own reading of the definitions, and every property it checked that matters is a theorem. What it could legitimately catch is a divergence between the compiled code and the kernel's evaluation of the same definitions; that needs the compiled path to be something a consumer runs, so it comes back (as a differential whose oracle is the kernel, never a hand-written expectation) when that path first ships.

## 4. Ran-evidence (the gate rule)
A check that never ran must not pass. Every test script prints `ran: NAME: N cases` (N > 0, the checks that were evaluated and held) and every concurrent gate prints its own count (`scripts/ran-gates.txt`); `scripts/run-tests-parallel.sh` and `scripts/ran-evidence.sh` fail a script or gate that exits 0 without it, with a zero count, or with a `SKIPPED` line, and a refused tool (exit 126, 127, 124, a guard message) is never a pass. The shared negative test is `scripts/test_ran_evidence.sh`. Honest weakness: a count proves a count was printed, not that every case was meaningful.
